# C 整数卷积参考实现

在项目根目录使用 GCC 编译和运行：

```sh
gcc -std=c99 -O2 -Wall -Wextra -Werror software/conv_int8.c software/test_conv.c -o software/test_conv.exe
./software/test_conv.exe
./software/test_conv.exe 1
```

默认验证已导出的前 10 张图片。必须先运行 `python/quantize.py` 生成 INT8 权重头文件和测试向量。重新导出权重后需要重新编译 C 程序。

## 文件用途

- `conv_int8.h`：卷积和重新量化接口。
- `conv_int8.c`：纯 C 计算，不依赖文件系统或 Python，可供后续 E203 移植。
- `test_conv.c`：PC 验证入口，读取十六进制 `.mem` 文件，逐元素比较两层卷积的累加值和 ReLU 后的量化值。第二层输入来自 Python 的 `pool1.mem`，因此这是独立层验证，不是完整 C 网络推理。

## 数值约定

输入和输出为 CHW，权重为 OIHW，按 C 顺序连续存储。卷积不翻转卷积核，步长 1、无填充，5×5 核。接口限定当前 LeNet 的规模：输入通道 1..6、输出通道 1..16、空间尺寸不超过 28。调用者提供足够大的、互不重叠的输入与输出缓冲区。

输入是已经量化的 INT8，而不是原始 0..255 像素；原始像素转换公式为 `(pixel * 127 + 127) / 255`，使用非负整数除法。

累加包含偏置。参考程序用 INT64 安全累加并检查最终 INT32 范围，结果超界返回 -2；这不保证硬件每一步 INT32 累加都不会溢出，设计硬件前还需分析累加边界。参数无效返回 -1，成功返回 0。返回错误时输出可能部分写入。

重新量化使用 INT64 乘积、每输出通道的 multiplier 和 shift（0..62）、最近舍入且半数远离零。ReLU 输出范围为 0..127，非 ReLU 为 -127..127。避免对负有符号数右移，因此舍入行为跨编译器一致。

输出尺寸为 `outputs × (height - 4) × (width - 4)`。`accumulators` 可为 NULL，其他指针必须有效。

当前程序是正确性参考，不是性能基准；PC 耗时不能作为题目的 RISC-V 软件基准。移植后需使用同一硬件计时器比较软件和加速器，并说明计时范围。后续可在证明累加安全后优化软件实现。
